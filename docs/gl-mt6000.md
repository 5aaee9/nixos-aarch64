# GL.iNet GL-MT6000

The GL-MT6000 (Flint 2) uses a MediaTek MT7986A and boots from eMMC through a
MediaTek BL2 plus FIP boot chain. It does not use the Rockchip loader layout or
the repository's systemd-boot/repart image defaults.

The board module is available as
`nixos-aarch64.nixosModules.gl-mt6000-kernel`. It adds the MT6000 Linux device
tree and the board's eMMC, Ethernet, Wi-Fi, USB, reset button, and status LED
nodes.

An experimental GPT + FIT image is available as
`packages.<system>.gl-mt6000-image`. It creates `u-boot-env`, `factory`, `fip`,
`cfg`, `log`, `kernel`, and `rootfs` GPT partitions. The `kernel` partition
contains a gzip-compressed U-Boot FIT image with the NixOS kernel, initrd, and
MT6000 DTB; the `rootfs` partition is labeled `rootfs`, matching the DTB boot
arguments. The current experimental layout uses a 64 MiB `kernel` partition
starting at sector 32768 and `rootfs` starting at sector 163840. `sgdisk` may
align the `factory` and `fip` entries to sectors 10240 and 14336.

Build it with:

```bash
nix build .#gl-mt6000-image
```

The raw image is under `result/sd-image/nixos-gl-mt6000.raw`. Before writing it,
verify the target device name with `lsblk`; then write the complete user-area
image only after unmounting its partitions:

```bash
sudo umount /dev/mmcblkX* 2>/dev/null || true
sudo dd if=result/sd-image/nixos-gl-mt6000.raw of=/dev/mmcblkX bs=4M conv=fsync,status=progress
sudo blockdev --rereadpt /dev/mmcblkX
```

Replace `/dev/mmcblkX` with the whole eMMC device, never a partition. This image
writes the GPT, `fip`, `kernel`, and `rootfs` user-area contents. It does not
write eMMC boot0, so install `preloader.bin` there only through the MT6000
recovery procedure after making a backup of the existing boot0 and user area.
Do not use a generic `dd` offset for BL2: the recovery tool and eMMC boot
partition configuration determine how boot0 is written.

The image contains the FIP in the user data area for convenience. The BL2
preloader still has to be installed in the eMMC boot partition using the
device's recovery procedure; a GPT image cannot represent the separate eMMC
boot area.

Build the boot firmware with:

```bash
nix build .#gl-mt6000-firmware
```

The result contains:

- `share/gl-mt6000/preloader.bin` — the MT7986 eMMC BL2 image;
- `share/gl-mt6000/bl31-uboot.fip` — the BL31 plus U-Boot FIP.

These files are bootloader artifacts for the MT6000 eMMC layout. They are not
written into a NixOS disk image automatically. Flashing BL2 or FIP changes the
boot chain and should follow the device's recovery procedure. A NixOS system
image still needs a board-specific eMMC GPT layout and a U-Boot compatible
kernel image before it can be flashed as a complete firmware image.
